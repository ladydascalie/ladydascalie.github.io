# darkmage.dev

Personal website of Benjamin Cable, built from data.

## Structure

| Path | Purpose |
| --- | --- |
| `cv.json` | **All real content** (theme-agnostic): bio, experience, skills, projects, contact, meetup, webring. Served at `/cv.json` |
| `src/themes/hexcore/template.js` | Default theme HTML template (`{{placeholders}}`, `{{@each path}}…{{/each}}` loops) |
| `src/themes/hexcore/style.css` | Default theme styles, layered on the design-system tokens |
| `src/themes/hexcore/script.js` | Default theme client-side behaviour (theme toggle) |
| `src/themes/hexcore/theme.json` | Default theme flavour data (class, circle, focus, rune tiers) |
| `src/themes/hexcore/favicon.svg` | Default theme favicon, copied into the build output |
| `src/themes/hexcore/check.mjs` | Acceptance test for the default theme |
| `src/themes/cypherpunk/*` | Previous terminal theme, still buildable with `--theme cypherpunk` |
| `src/themes/resume/*` | Plain resume theme, renders `cv.html` |
| `src/template-engine.js` | Placeholder, loop and filter engine shared by every theme |
| `src/vendor/design-system/v0.3.0/` | Vendored Runbooks design tokens, font faces, woff2 fonts and licences. See its `VENDOR.md` |
| `build.mjs` | Static site generator |
| `.github/workflows/pages.yml` | Build and deploy to GitHub Pages |
| `dist/` | **Generated** output directory, ignored by git |
| `index.html`, `cv.html` | Pages generated by an earlier build and still committed. The build no longer writes them |
| `llms.txt` | Points LLMs and scrapers at `cv.json` and `cv.html` |
| `CNAME` | Custom domain, copied into `dist/` |
| `.well-known/` | Matrix and Keybase files, copied into `dist/` |
| `.nojekyll` | Disables Jekyll on Pages, copied into `dist/` |

## Building

```sh
node build.mjs                       # hexcore, into dist/
node build.mjs --theme cypherpunk    # the previous terminal theme
node build.mjs --out some/dir        # write somewhere else
```

The default theme is `hexcore`. When `src/themes/hexcore/template.js` is
missing, the build falls back to `cypherpunk`. The default output directory is
`dist/`.

The build deep-merges `cv.json` with the selected theme's `theme.json`
(array items merge index-wise; a flavour entry with a `"$match": "<name>"`
key merges into the content item whose `name` field matches, independent of
position). It inlines CSS in this order: design-system `tokens.css`, then
`fonts.css`, then the theme's `style.css`. Theme CSS and JS are inlined, so
each page is a single static file.

It also renders `cv.html` from `cv.json` with the resume theme (no flavour
data) and injects meta, Open Graph and schema:Person JSON-LD tags into both
pages. Canonical and Open Graph URLs point at `https://darkmage.dev/`. A
favicon link and `og:image` are added only when the theme ships those files.

Alongside the two pages, the build copies `cv.json`, `llms.txt`, `CNAME`,
`.nojekyll`, `.well-known/`, the design-system `fonts/` (so the `fonts/`
URLs in `fonts.css` resolve) and the portrait into the output directory.

Print `cv.html` to PDF for an ATS-friendly CV. Arrays render with
`{{@each}}` loops, so adding or removing entries in `cv.json` just works with
no template edits. A failed build warns about any unresolved
`{{placeholder}}`.

Run the theme check with:

```sh
node src/themes/hexcore/check.mjs
```

## Deploying

`.github/workflows/pages.yml` builds the site and deploys it to GitHub Pages
on every push to `master`, and on manual dispatch. The job runs `node
build.mjs`, uploads `dist/` as the Pages artefact, then deploys it. There is
no `npm install`: the build has no dependencies.

## Remaining manual steps

These need the repository or DNS owner and cannot be done from this tree:

1. Switch the Pages source to GitHub Actions in the repository settings.
   The site is currently published by the legacy Jekyll builder from the
   `master` branch root, which would ignore `dist/`.
2. Set the custom domain to `darkmage.dev` in the Pages settings.
3. Enforce HTTPS once the certificate is issued for `darkmage.dev`.
4. Point DNS at GitHub Pages: an `A` or `ALIAS`/`ANAME` record for the apex
   domain, and a `CNAME` record for `www` aimed at the Pages host.
